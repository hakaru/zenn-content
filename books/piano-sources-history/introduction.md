ピアノ音源を 8週間で 5本作った。

```
elepiano       ──→ iRhodes        ──→ TineModeler     ──→ TineModeler2   ──→ TineModeler3
(Pi 5 / C++)      (iOS / Swift)        (macOS / 物理)      (Python / DDSP)    (AUv3 / Swift+C++)
                                                                              = RhoDex

2026-03-01      2026-03-10           2026-03-11          2026-03-17        2026-04-26
～03-10         ～03-?                ～03-16             ～04-04           (現在)
```

毎週世代交代のペースで 5本のリポジトリが生まれた。テーマは一貫していて、**サンプリングと物理モデリングと機械学習をどう混ぜるか**。

最初の elepiano は Raspberry Pi 5 上で Keyscape のサンプルを鳴らす音源で、サンプリングが主役。最後の TineModeler3（RhoDex）は AUv3 プラグインで、物理モデル + DDSP（Differentiable DSP, 微分可能 DSP）残差学習を CoreML でリアルタイム合成する。**サンプルは配布物から完全に外れた**。

この本は、その 8週間で「サンプル中心 → 物理モデル単独 → 物理 + DDSP ハイブリッド」と比重が大きく動いた過程を、各世代の技術選択と反省と一緒に並べたもの。

## 各章の主役

| # | プロジェクト | 一言で |
|---|---|---|
| 1 | **elepiano** | Pi 5 + iOS BLE-MIDI リモコン。Keyscape SpCA フォーマット逆エンジニアリングと setBfree オルガン |
| 2 | **iRhodes** | iOS へ完全移植。サンプル + 物理モデルのタイムオーバーラップ方式でファイル 2.7GB → 186MB |
| 3 | **TineModeler** | サンプル無しで Rhodes をどこまで再現できるか。Symplectic Euler + CMA-ES |
| 4 | **TineModeler2** | 物理モデルが取りこぼす残差を DDSP で学習。Mac M4 Air + Vast.ai で総額 ¥3300〜 |
| 5 | **TineModeler3** | RhoDex。Swift 5.10 C++ Interop + AUv3 + CoreML streaming で製品化 |

最後の2章で、5世代を貫く技術選択の変遷と、反省と次の指針をまとめる。

## 想定する読者

- オーディオプラグインや楽器音源を作っている / 作りたい人
- リアルタイムオーディオで C++ / Swift / DSP / ML をどう同居させるか興味がある人
- 物理モデリングと機械学習を「対立」じゃなく「協調」で使うアプローチに興味がある人

逆に「ピアノ音源の使い方」や「DAW の設定」の話は出てこない。**作る側の話**しかない。

## この本に書いてないこと

- ピアノ音源として完成した最終音色のサウンドサンプル *（製品化前なのでまだ出せない）*
- 商用配布のための法務的な詳細
- マルチ機種展開（LA Custom, Wurlitzer など）— 学習データセット拡張は構想だけで未着手

それと、これは Rhodes Electric Piano を題材にした話で、いわゆるアコースティックピアノ（グランドピアノ）の音源開発の話ではない。Rhodes の発音体は「ティネ」と呼ばれる金属棒で、これを物理モデル化するから *Tine* Modeler。

## 開発ツールについて

8週間で 5本というペースは、Claude Code や Codex のエージェントを並走させていたから出せた数字で、自分一人で書き切ったわけではない。各章で「ここはエージェントに任せた」「ここは手で書いた」を分けて書くわけではないけど、コミット数（elepiano 86 commits / 10日、TineModeler 156 commits / 5日）の異様さは AI 並走の副産物として頭に置いて読むといいと思う。
