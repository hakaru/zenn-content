## 気象庁が2021年にセミの観測やめたの、知ってた？

俺は知らなかった。

正確には「生物季節観測」っていう、桜の開花・カエデの紅葉・**セミの初鳴き**みたいな季節の便りを気象台が記録し続けてきた仕組みがあって、2021年にこれが大幅縮小された。動物系はほぼ全廃、セミの初鳴き日もここで途切れた。数十年ぶんの時系列が、静かに止まった。

で、**都知事杯オープンデータ・ハッカソン2026**の応募を考えてて、テーマを探してるうちにこれに行き当たった。エントリー締切は **7/27(月) 17:00**。まだ何も作ってない。この記事は着手前の設計メモ、という位置づけ。

作ろうとしてるのはこれ。

**「セミ前線 TOKYO」** — 桜前線のセミ版。街に置いたマイクとスマホがセミの鳴き声を種別に自動判定して、「いつ・どこで・どのセミが鳴き始めたか」を地図にする。途切れた公的観測を、エッジAI（= 端末の中で推論を完結させるやり方）と市民科学で東京から再開する、というやつ。

なんでこれを俺がやろうと思ったかというと、 *セミの鳴き声の分類って、普段やってる音のシンセシスをちょうど逆向きにした話*だから。

## 音を「作る側」から「聴き分ける側」へ

普段は DX7 互換の FM 音源とか、Rhodes の物理モデリングとか、 **音を合成する**方の開発をしてる。オペレータの位相を積んで、スペクトルを設計して、狙った音色を出す。

セミの種判定はこれのちょうど裏返しで、 **入ってきた音のスペクトルを見て、何が鳴ってるか当てる**。しかもセミって、種ごとの音響的な特徴がびっくりするほどクッキリしてる。

- **アブラゼミ** — 「ジリジリ」。帯域の広いノイズ様の連続音
- **ミンミンゼミ** — 「ミーンミンミン」。はっきりした周期変調（振幅がゆっくり上下する）
- **ニイニイゼミ** — 「チーーー」。純音に近い持続音
- **ヒグラシ** — 「カナカナカナ」。朝夕限定、周波数がスイープするフレーズ
- **ツクツクボウシ** — 「ツクツクボーシ」。明確なフレーズ構造を持つ、いわば *歌*
- **クマゼミ** — 「シャシャシャ」。これが今回の主役

メルスペクトログラム（= 人間の聴覚に合わせて周波数軸を圧縮した音の画像）に落とすと、この6種は目で見ても違いが分かるレベルで別物。だから重量級のモデルは要らなくて、軽いCNNで十分に戦えるはず、という読み。 *ここは合成側で培った「音を周波数で見る」感覚がそのまま効く*と思ってる。

### なんでクマゼミが主役か

クマゼミはもともと西日本のセミ。それが温暖化とヒートアイランドで東へ進出してて、 **都心での検出そのものが気候変動のローカル指標**になる。「東京のどこでクマゼミが鳴き始めたか」を毎年地図に載せられたら、それは体感できる気候データになる。桜前線が春の便りなら、こっちは *温暖化の便り*。

## プライバシーを先に片付ける — 生音声は端末から出さない

街にマイクを置く、と言った瞬間に出てくるのが「それ盗聴じゃん」問題。ここを先に潰しておかないとサービスとして無理。

なので設計の芯を **「生音声は端末の外に出さない」**に置く。

- スマホは **ブラウザの中**で推論する（WebAudio でスペクトログラムを作って、tf.js / ONNX Runtime Web でその場で分類）
- マイコンノードも **端末内**で特徴量抽出 → 分類する
- サーバに送るのは **「種・信頼度・粗い位置メッシュ・時刻」だけ**

会話が混ざろうが、生の波形はそもそも端末から一歩も出ない。これは「気持ちの問題」じゃなくて **技術で担保する**ところがミソで、ハッカソンの技術賞を狙うなら一番の訴求点になる、と踏んでる。

## 3層のセンシング網

参加はソロなので、無理せず「誰でも入れる入口」と「常設で貯める仕組み」を分けた3層構成にする。

| 層 | デバイス | 役割 |
|---|---|---|
| 市民参加層 | スマホ PWA | 「10秒きくだけ」。インストール不要、ブラウザ内推論 |
| 常設ノード層 | M5Stack | ベランダ・公園に置く数千円の常設マイク |
| 基準局層 | Raspberry Pi | フル精度モデルで判定、M5Stack のゲートウェイ兼用 |

手元に M5Stack も Raspberry Pi もある。M5Stack はマイク内蔵・Wi-Fi 付きで常設ノードにドンピシャなんだけど、推論能力は非力なので **特徴量抽出だけ端末でやって、重い分類は Pi かクラウドに逃がす**構成も許容にしておく。ここはハッカソン当日に実機を触りながら詰める。

バックエンドは応募者に無料提供される **Cloudflare（Workers / D1 / R2）**をそのまま使う。サーバレスなので運用コストがほぼゼロで済むし、提供ツールをフル活用してるという点でも筋がいい。

## オープンデータとどう接続するか

ハッカソンの必須条件が「オープンデータor民間データの活用」。セミの観測データを自前で集めるだけだと弱いので、公的データと噛ませて **意味**を足す。

- **気象庁 生物季節観測の過去データ** — 途切れたセミ初鳴き日の歴史系列。 *ここに自分たちの観測を接ぎ木して系列を再開する*のが物語の核
- **東京都オープンデータカタログ** — 都立公園一覧、みどり率・緑被率
- **アメダス／都の大気環境測定局** — 気温。初鳴き日 × 積算温度の相関を可視化する

東京都は生物多様性地域戦略アクションプラン2025で、都立公園31箇所を生物多様性の拠点に位置づけてモニタリングを重視してる。 *つまり「連続観測できる仕組み」への行政ニーズは既にある*。そこに市民科学の観測網を差し込む、という接続にする。

## ソロでどこまでやるか — 広げない勇気

一人なので、盛りたい気持ちを抑えるところが一番大事。

やらないこと(= 構想スライドで触れるだけにする):

- **鳥の鳴き声**への拡張（東京都鳥類繁殖分布調査というデータがあるので将来性はある。でも鳥は種数が桁違いで、MVPに入れたら確実に溺れる）
- 複数ノードの広域展開
- 通年運用

MVPは **セミ6種 × PWA × M5Stack 1台**に絞る。これで「動くデモ」を確実に出すことを最優先にする。

デモの絵はもう決めてて、屋外に依存すると詰むので **スピーカーからセミ音源を再生 → 実機がリアルタイムで種名を当てて地図にプロット**、という室内で完結する構成にする。8月なのは幸いで、 *セミの実音が録りたい放題*だから学習データ集めには困らない。

## リスクは正直に

| 気になってること | どうするか |
|---|---|
| 分類精度が出ない | セミは種ごとの音響特徴が明瞭。スペクトログラム分類は比較的素直な問題のはず |
| 当日デモが動かない | 音源再生 → 実機判定の室内構成。屋外・生き物依存をなくす |
| ソロで工数が溶ける | 6種特化・ハード1台・PWA に絞る。鳥も広域も後回し |
| M5Stack の非力さ | 特徴量抽出だけ端末、分類は Pi/Workers に逃がす二段構え |

一番の不確定要素は「M5Stack でどこまで端末内推論を回せるか」で、こればっかりは実機で測らないと分からない。 *ここが最初に手を動かす場所*になりそう。

## というわけで、まだ何も作ってない

普段は音を作る側にいる人間が、同じスペクトルの知識で今度は音を聴き分ける側に回ったら何ができるか。 *桜前線のセミ版*、というワンフレーズが自分でも気に入ってるので、まずはそこに賭けてみる。
